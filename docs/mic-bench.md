# マイクの聞き取りのベンチマーク

本物の楽器と声の録音を、アプリと同じ手順で聞かせて、1 音ずつ答えを確かめた結果（2026-11-13、1.3.0）。
手順と録音は README の「マイクの聞き取りの確かめ方」。`npm run bench:fetch && npm run bench:mic && npm run bench:chords` で同じ結果になる。

- 録音：アイオワ大学の楽器音（University of Iowa Musical Instrument Samples。どんな目的にも制限なく使ってよいと案内されている）、
  男声（vocobox/human-voice-dataset、MIT ライセンス）
- 聞き方：48 kHz・20 ms ごと・感度「ふつう」・部屋の雑音（-56 dB）を足す。大きさは強さごとにそろえる（mf：いちばん大きいところで -26 dB）
- 正しく 1 回：その音で、正しい高さ（オクターブまで）を 1 回だけ答えた。最初がちがう：最初の答えが違う高さ。
  余計に答えた：正しく答えたあと、同じ音でもう一度答えた。空答え：音のないところで答えた。
  数えない音：弾き手の音程が半音の途中（±35 セントより外）で正解が決まらない音と、録音の雑音

## 和音（コード聞き取り）

本物のピアノの 1 音ずつ（mf、ド3〜ド6）を足し合わせて作った和音。11 種類 × 根音 12（ド3〜シ3）× 転回形。
人が弾くように、音ごとに出だしを 0〜15 ms ずらし、強さを 0.8〜1 倍にした。出す種類を絞らず、全 11 種類から選ばせた結果。

## わかっている弱いところ

- 鍵盤を押さえたまま（弦が鳴り続けたまま）同じ音を 0.3 秒ほどで連打すると、2 回めを数えないことがある（ピアノの弦のうなりと見分けられない）。鍵盤をいったん離せば数える
- 弾き手の音程が半音のちょうど真ん中あたりだと、答えない（どちらの音か決まらない）。チューナーで確かめられる
- 指定なしで歌うと、歌い始めのすくい上げが落ち着くのを待つので、答えは 0.4 秒ほどかかる。指定なしのギターは、出だしの高さの動きで待つことがあり 76% ほど（楽器を「ギター」にすると 87%）
- ピチカートの低い G 線・高い E 線で、1 オクターブ上（倍音）と答えることがある（音名で答えるゲームでは同じ答え）
